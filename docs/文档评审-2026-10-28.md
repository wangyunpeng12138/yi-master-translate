## 一、总体结论

| 文档 | 结论 | 可用性 |
| --- | --- | --- |
| 功能梳理.md | 覆盖面优秀（16 分区 + popup + 侧栏 + 页面内能力齐全），数据级断言绝大多数正确；**6 处默认值/键名判断与配置不符**，3 处表述不精确 | 作为"功能地图"可直接用；作为"验收基线"需先修正第 2.2 节 |
| 实现方案.md | 技术选型、分层、阶段划分、裁剪判断基本合理；但**2 处事实错误会误导实现**（DNR 用途、scripting 权限），**1 处简化决策有实际风险**（版本化覆盖），**3 处 MV3 硬约束未覆盖** | 架构可执行；需按第 3.2 / 3.3 节修订后再进入 P2 |

一句话：**文档质量高于一般逆向梳理，但"默认值"这一层存在系统性偏差** —— 原因是把"UI 上看到的当前状态"写成了"配置默认值"，而原版存在版本化覆盖（`.add_v.[版本]`）和登录态差异。

### 2.3 结构性建议（提升可维护性）

1. **每行加"证据键路径"列**（如 `generalRule.imageRule.imageTranslateProvider`）。现在多数行只有"默认值"，一旦原版升级就无法 diff 出偏差。
2. **区分两种"默认"**：`配置默认值`（default_config.json）与 `UI 初始显示值`（可能被版本覆盖、登录态、地区、实验开关改变）。本次 6 处偏差全部源于混用。
3. **附一份关键键值快照**（`docs/baseline-config-snapshot.json`，只取本文提到的键），后续升级可脚本 diff。
4. **无法本地核实的项显式标注**：会员额度（每月免费 100 张）、版权年份、云端 AI 专家数据、规则同步时间戳 —— 这些只能来自线上，建议打「未验证」标记。

## 三、实现方案.md 合理性评估

### 3.1 判断合理、可直接执行的部分

| 项 | 评价 |
| --- | --- |
| TS + WXT + Vue3 + Pinia + Element Plus + vue-router hash | ✅ 选型与"复刻 UI + 全中文生态"目标匹配；hash 路由对齐原版 `#general` 直链 |
| `core/` 作为三上下文唯一共享层 | ✅ 正确做法，避免 SW / content / UI 逻辑漂移 |
| 沿用"guard 轻量 → 动态注入 main"两级链 | ✅ 与原版实现一致（已核实 `content_guard.js` 用 `import(getURL('content_main.js'))`） |
| 配置三层合并（默认 → 站点规则 → 用户） | ✅ 方向对（细节见 3.2-3） |
| 裁剪：官网链接、会员体系、云同步、遥测、EPUB、OneAIFW | ✅ 判断准确，这些确实强耦合官方服务 |
| 分阶段 P0–P8 + 每阶段验收清单 + commit | ✅ 与"实测必验证"的协作方式匹配 |

### 3.2 必须修正的事实错误

**① DNR 用途判断错误（§2.2-3、§7.2）**

方案原文：「32 条静态规则**不是**给翻译 API 改头，而是给漫画/图片站图片请求设置 Referer/Origin/DNT…」

实际拆分（逐条核对）：

| 类别 | 条数 | 例子 |
| --- | --- | --- |
| **翻译 API 改头** | 7 | `www2.deepl.com/jsonrpc*`（含移除 cookie）、`api.deepl.com/jsonrpc*`、`w.deepl.com/oidc/token`、`transmart.qq.com/api/imt`、`translate.volcengine.com/crx/translate/v1/`、`dict.youdao.com/jsonapi_s*`、`httpstat.us/429`（连通性测试） |
| 漫画/图片 CDN 防盗链 | 25 | `i.pximg.net`、`stcdn.manhwato.com`、`*.sinaimg.cn`、`data.tnlycdn.com`、`viewer.comic-growl.com` 等 |
| 本地 Ollama 头豁免 | 2 | `http://*:11434`、`http://*:1234` |

→ 影响：方案 §7.2 写「webRequest ❌ 移除（不做翻译 API 改头）」是把两件事混在一起。**改头靠 DNR，不靠 webRequest**。若 P2 之后要接 DeepL / 腾讯 / 火山 / 有道 免费通道，必须保留"API 改头"这类规则，否则那些通道会被 Origin/Referer 校验挡掉。建议把 DNR 规则集拆成两个文件：`rules-image.json`（防盗链）与 `rules-api.json`（改头），后者按需启用。

**② 权限表错误：原版没有 `scripting` 权限（§7.2）**

`manifest.json` 的 `permissions` 为：`storage, activeTab, contextMenus, webRequest, declarativeNetRequest(WithHostAccess/Feedback), offscreen, sidePanel` —— **无 `scripting`**。引擎注入走 `content_guard.js` 里的 `import(chrome.runtime.getURL("content_main.js"))`。

→ 影响：新工程同样不应申请 `scripting`；WXT 默认把 content script 打成 IIFE 单文件，"两级注入"需要手动配置 WAR + 可被 `import()` 的 ESM chunk。**建议 P0 加一个 spike**：验证 `content script → import(WAR chunk)` 在 WXT 下可行，否则 P3 才发现要返工。

**③ 简化合并的风险：版本化覆盖不能简单丢弃（§4.4）**

方案称「不实现 `.add_v.[版本]` 版本化操作符」。但实际生效值就依赖它：

| 键 | 基础默认 | 版本化覆盖 | 生效结果 |
| --- | --- | --- | --- |
| `pcFloatBall` | `enableSidePanel: true`、`enablePinSidePanel: true` | `.add_v.[1.30.3] = {false, false}` | 侧边栏按钮**默认隐藏**（正是功能梳理 §11 观察到的现象） |
| `inputTrailingTriggerKeyRepeatTimes` | `3` | `.add_v.[1.24.1] = 2` → `.add_v.[1.25.1] = 3` | 3 次 |
| `inputTrailingTriggerKeyTimeout` | `200` | `.add_v.[1.24.1] = 300` | 200（更高版本未覆盖） |

→ 建议：不是"不实现"，而是**在 defaults.ts 里一次性 flatten 成生效值**，并在附录 A 记录"某键来自版本化覆盖"。否则会出现"配置写 true、UI 却显示关"的诡异 bug。

**④ 裁剪表漏项：「无字幕翻译」不可实现（§1.2）**

功能梳理 §17 提到插件版支持"无字幕翻译"。该能力依赖官方云端 ASR，本地无法复刻。方案 P8 只写"视频字幕引擎（规则驱动子集）"，未声明此项裁剪。建议在 §1.2 明确列为不实现，避免 P8 验收踩空。

**⑤ 服务命名需统一（§4.5 注释）**

`bing.ts` 注释写"默认服务，同原版 bing-free"，但原版默认 id 是 `bing`，`bing-free` 是 `extends: bing` 的免费变体。适配器设计上应说明二者关系（同一实现、两个 id、一个带 free 分组标记），否则导入原版配置时会出现 `bing-free` 找不到适配器。

### 3.3 技术缺口与风险（建议补入方案）

| # | 风险点 | 现状 | 建议 |
| --- | --- | --- | --- |
| 1 | `chrome.storage.sync` **单键 8KB** 限制 | 方案只写"≤100KB" | 用户配置按分区拆 key，或整包落 `local`，sync 只放少量偏好；术语库/缓存明确落 `local` |
| 2 | `sidePanel.open()` **必须用户手势** | §4.3 协议有 `panel:open`，background 直接调用会抛错 | 协议注明调用链：popup 按钮 / 内容脚本点击 → background 转发；不可由 SW 主动调用 |
| 3 | `captureVisibleTab` **每秒 2 次**且只能抓当前可见 tab | 圈选翻译只写了一句 | 补时序：页面内画遮罩选区 → 请求 background 截图 → canvas 裁剪 → offscreen OCR；并加节流与失败重试 |
| 4 | 注入脚本必须 **MAIN world** | 方案写"WAR 注入"，未提 world | `image/inject.js`（hook `drawImage`/`createImageBitmap`）、`video-subtitle/inject.js`（hook XHR）必须跑在主世界，否则 hook 无效 |
| 5 | 页面 UI 需 **Shadow DOM 隔离** | §4.6 未提 | 悬浮球/划词弹窗/译文 wrapper 建议 Shadow DOM + `inject.css`，否则站点 CSS 会污染（原版靠 `wrapperPrefix`、`translationBlockStyle` 等对抗） |
| 6 | 字幕技术路线未定 | P8 只写"规则驱动子集" | 明确：`<track>` 元素拦截 + XHR/fetch hook 抓 vtt + MutationObserver + 自绘字幕层；214 站点里规则只负责 selector/容器差异 |
| 7 | 免费 bing 通道不稳 | 已声明风险 | 补降级链：bing → google → 自定义 API；P2 验收加"连续 100 段成功率"指标 |
| 8 | P3 工作量偏乐观 | 一天内做 guard 链 + walker + renderer + 3 主题 + 悬浮球 + badge | 拆 P3a（链路打通：Alt+A → 段落识别 → 纯文本双语插入）与 P3b（主题/仅译文/全区域/同语言检测/加载态） |
| 9 | 附录 A 映射表只有 13 条 | 功能梳理里进阶 17 + 字幕 12 + 划词 8 + 输入 6 ≈ 40+ 键 | 先做"全量键清单 → 保留/裁剪"表，再进入 P5/P6，否则会边做边发现漏项 |
| 10 | 验收引用错误基线 | 附录 B 让 P5/P6 按功能梳理逐项点验，但该文档 2.2 节有 6 处默认值错误 | 先修文档再当基线（例如按现状会把"划词默认开"验成 bug） |
